This is the exact case the skill flags as "defaults, not a lock". Recording it rather than changing the table.

**Amended after Ben's review: X moved to fy=0.56.** The first pass at fy=0.44 put the headline straight across both faces. At fy=0.56 the subjects sit clear above the text block, both are still fully in frame, and there is headroom above the teenager. fy=0.62 was also tested and clips the tops of both heads, so 0.56 is the ceiling on this master. X asset re-rendered and the approval page rebuilt.

Worth carrying forward: on a 16:9 crop from a 9:16 master, the useful fy is the one that clears the text block, not the one that centres the subject. The 16:9 target keeps only about 38% of the trimmed source height, so faces land in the overlay zone unless fy is pushed well past 0.5.

## Checker defects found and fixed this run

Both initial FAILs were defects in the QA script, not in the copy. Fixed in the harness, recorded here so a future run does not re-trigger them.

1. **Double-hyphen check matched markdown horizontal rules.** The section separators between captions in the drafts markdown are structure, not prose. The check must strip lines matching `^---\s*$` before greping for `--`. Without that, every well-formed drafts file fails.

Suggested edit to `gcse-boss-daily-content/SKILL.md` Phase 8, for Ben: state that the em dash grep runs on prose only, after markdown structural syntax and HTML attributes are stripped.
